# 第1部 課題内容

## 1. 課題

顧客の保有株式のポートフォリオを表示する、簡易なWebアプリケーションを作成する。

## 2. 内容

- 添付のJSONファイルをAPIのダミーレスポンス(モックデータ)として利用し、データを取得する。
- APIのレスポンスから顧客の保有株式情報を取得し、後述の要件を満たすようにUIを動的に構築する。

### 2.2 ワイヤーフレーム

別途添付の画像を参照。読み取れる構成は次のとおり。

- 画面上部にドーナツ型のパイチャートを配置する。各要素の間には隙間がある。
- チャートの中央に、資産総額(例: `¥115,500`)と評価損益(例: `+15.5%(+¥15,500)`)を表示する。
- チャートの下に、保有銘柄の一覧を表示する。各行の構成は次のとおり。
  - 左: 銘柄ロゴ
  - 中央の上段: 銘柄名(例: `S&P 500 ETF (Vanguard)`)
  - 中央の下段: ティッカーシンボルと保有割合(例: `VOO / 39.8%`)
  - 右の上段: 保有金額(例: `¥45,969`)
  - 右の下段: 評価損益(例: `+12.87%(+¥5,242)`)
- 注記「クリックでフォーカスする」(チャートの要素を指す)

## 3. UI要件

- UIの大枠は、ワイヤーフレームと同様になるように実装する。
- 画面上部には、顧客のポートフォリオを表すパイチャートを配置する。
  - パイチャートは顧客の保有銘柄を構成要素とし、各要素の比率は銘柄の保有割合に合わせる。
  - パイチャートは12時の位置を起点とし、保有割合の大きい順に時計回りに並べる。
- パイチャートはドーナツ型で表現し、中央に顧客の「資産総額(円)」「評価損益額(円)」「評価損益率(%)」を表示する。
  - 評価損益がプラスの場合は評価損益額・率のテキストを緑、マイナスの場合は赤、ゼロの場合はグレーで表示する。
- パイチャートの下に、パイチャートの構成要素でもある保有銘柄の情報を一覧で表示する。
  - 一覧では銘柄ごとに「銘柄ロゴ画像」「銘柄名」「ティッカーシンボル」「評価損益額(円)」「評価損益率(%)」を表示する。
- パイチャートの要素がタップ/クリックされたら、その要素をフォーカスし、他の要素は半透過で表示する。
  - 保有銘柄の一覧でも、フォーカスされた銘柄以外を半透過で表示し、フォーカスされた銘柄のみを目立たせる。
  - フォーカスされた要素以外がクリックされたら、フォーカスを外す。

※ ワイヤーフレームやUI要件で言及されていない仕様・デザインは、回答者が自由に決めて実装してよい。自分が納得のいくUI/UXに仕上げて提出すること。

## 4. 制約

- Next.jsを用いてSPAを構築すること。バージョンはできるだけ最新版を利用すること。
- TypeScriptで記述すること。
- リンターとフォーマッターを適切に設定すること(使用ツールは任意)。
- Google Chrome最新版での正しい動作を保証すること。
- PC/スマートフォン表示に対応すること(レスポンシブデザイン)。
- パイチャートには、サードパーティ製のグラフライブラリを利用してもよい。
- スタイルは自前で記述すること。
  - CSS in JS、CSS Modules、Sassなどは利用可。
  - スタイルに関連するライブラリとして、以下も利用可。
    - グラフライブラリなどに内包されているスタイル
    - リセット系のCSSライブラリ
    - Tailwind CSSなどのユーティリティファーストなCSSフレームワーク
- テストケース/テストコードを作成すること(使用ツール・テスト対象は任意)。
- テスト実行時にエラーが発生しないこと。
- `pnpm install` / `pnpm dev` で起動し、`http://localhost:3000` で動作確認できること。

# 第2部 実装計画

## 7. 技術選定

| 項目                    | 採用                                                     | 理由                                                                                                                                     |
| ----------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| フレームワーク          | Next.js(最新版、App Router)+ React(最新版)               | 制約「できるだけ最新版」に対応する。                                                                                                     |
| 言語                    | TypeScript(strict)                                       | 制約に対応する。                                                                                                                         |
| パッケージマネージャー  | pnpm                                                     | 制約「`pnpm install` / `pnpm dev`」に対応する。                                                                                          |
| スタイル                | Tailwind CSS v4 + CSS変数(デザイントークン)              | 制約で利用可。色・余白を変数で一元管理し、ダークモードにも対応する。                                                                     |
| パイチャート            | 自前のSVG実装(ライブラリ不使用)                          | 「12時起点・降順・時計回り」「要素間の隙間」「フォーカス時の半透過」「キーボード操作」をすべて意図どおりに制御するため。依存も減らせる。 |
| データ取得              | Route Handler(`/api/portfolio`)+ クライアントからのfetch | 本物のAPIに近い形でモックJSONを返し、SPAとしてクライアント側で取得する。                                                                 |
| レスポンス検証          | Zod                                                      | APIレスポンスを実行時に検証し、型もスキーマから生成する。不正なデータは画面のエラー表示につなげる。                                      |
| リンター/フォーマッター | ESLint(eslint-config-next)+ Prettier                     | Next.js標準の構成で、評価者がそのまま実行できる。                                                                                        |
| テスト                  | Jest + React Testing Library、Playwright                 | ロジックとコンポーネントはJest、実際のブラウザでの動作(PC/スマートフォン)はPlaywrightで確認する。                                        |

## 8. ディレクトリ構成

機能単位でまとめる構成(feature-based)を採用する。参考: https://www.robinwieruch.de/react-folder-structure/

この課題は1画面のため、ルーティングは `app/page.tsx` のみとし、ポートフォリオ機能に関するコードを `features/portfolio/` に集約する。複数の機能で使う汎用部品は `components/`・`hooks/`・`utils/` に置く。

```

│   ├── layout.tsx
│   ├── page.tsx                      # 画面の組み立てのみ(ロジックは持たない)
│   ├── globals.css                   # デザイントークン(CSS変数)
│   └── api/
│       └── portfolio/
│           └── route.ts              # モックJSONを返すAPI
├── features/
│   └── portfolio/
│       ├── api/
│       │   └── fetch-portfolio.ts    # APIの呼び出しとレスポンス検証
│       ├── components/
│       │   ├── portfolio-view.tsx        # チャートと一覧をまとめ、フォーカス状態を管理する
│       │   ├── donut-chart.tsx           # SVGのドーナツチャート
│       │   ├── portfolio-summary.tsx     # チャート中央の資産総額・評価損益
│       │   ├── holding-list.tsx          # 保有銘柄の一覧
│       │   └── holding-list-item.tsx     # 一覧の1行
│       ├── hooks/
│       │   └── use-portfolio.ts      # 取得状態(読み込み中・成功・エラー)の管理
│       ├── mocks/
│       │   └── portfolio.json        # 添付のダミーレスポンス
│       ├── schemas.ts                # Zodスキーマと型
│       └── utils/
│           ├── sort-holdings.ts      # 保有割合の降順ソート
│           └── donut-geometry.ts     # 各要素の角度・SVGパスの計算
├── components/
│   └── asset-logo.tsx                # 読み込み失敗時に代替表示するロゴ画像
```

## 9. 仕様の解釈と設計判断

### 9.1 パイチャート

- 保有割合の降順で並べ、12時の位置を起点に時計回りで描画する。
- 各要素の角度は `holding_ratio` から計算する。合計が100%にならないデータも、合計で正規化して円がずれないようにする。
- ワイヤーフレームに合わせて、要素間に一定の隙間を設ける。
- 色は銘柄ごとに、判別しやすい配色(パレット)から割り当てる。一覧の各行にも同じ色を表示し、チャートとの対応がわかるようにする。

### 9.2 チャート中央の表示

- 資産総額・評価損益額・評価損益率を表示する。表示形式はワイヤーフレームに合わせる(例: `¥115,500` / `+15.5%(+¥15,500)`)。
- 評価損益の色は、プラスが緑、マイナスが赤、ゼロがグレー。色だけに頼らず、`+` / `-` の符号も必ず表示する。

### 9.3 保有銘柄の一覧

- 要件の項目(ロゴ・銘柄名・ティッカー・評価損益額・評価損益率)に加えて、ワイヤーフレームにある保有金額と保有割合も表示する。
- ロゴ画像の読み込みに失敗した場合は、ティッカーの頭文字を代わりに表示する。

### 9.4 フォーカスの挙動

UI要件の「フォーカスされた要素以外をクリックされたらフォーカスを外す」は、次のように解釈する。

| 操作                                             | 結果                                   |
| ------------------------------------------------ | -------------------------------------- |
| フォーカスなしの状態で、チャートの要素をクリック | その要素をフォーカスする               |
| フォーカス中の要素を再度クリック                 | フォーカスを外す                       |
| 別の要素をクリック                               | その要素にフォーカスを移す             |
| 要素以外(背景・余白)をクリック                   | フォーカスを外す                       |
| 一覧の行をクリック(追加仕様)                     | チャートと同じくフォーカスを切り替える |
| Escキー(追加仕様)                                | フォーカスを外す                       |

- フォーカス中は、チャート・一覧の両方でフォーカス以外の要素を半透過にする。フォーカスした要素は、チャート上で少し強調する。
- 追加仕様: フォーカス中はチャート中央の表示を、その銘柄の保有金額・評価損益に切り替える。外すと全体の表示に戻る。

### 9.5 アクセシビリティ・品質

- チャートの各要素をボタンとして扱い(`aria-pressed`)、キーボード(Tab・Enter・Space)でも操作できるようにする。
- 「動きを減らす」設定(`prefers-reduced-motion`)が有効な場合は、アニメーションを止める。
- 読み込み中はスケルトンを、取得失敗時は再試行ボタン付きのエラーを表示する。
- ダークモードに対応する。

### 9.6 レスポンシブ対応

- スマートフォンを基準に縦一列で配置し、PCでは中央寄せで最大幅を設ける。
- チャートは画面幅に合わせて拡大・縮小する(SVGの `viewBox` を使用)。
- タップしやすさのため、操作できる要素は十分な大きさを確保する。

## 10. テスト方針

| 種類                 | ツール                                      | 対象                                                                                         |
| -------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 単体テスト           | Jest                                        | 書式(金額・割合・符号)、損益の色区分、降順ソート、角度計算(12時起点・時計回り・合計の正規化) |
| コンポーネントテスト | Jest + React Testing Library                | 中央表示、一覧の表示項目、フォーカス操作(9.4の表の各操作)、ロゴ読み込み失敗時の代替表示      |
| E2Eテスト            | Playwright(PC・スマートフォンの2画面サイズ) | APIからの取得と表示、クリックでのフォーカスと解除、レスポンシブ表示                          |

`pnpm test` と `pnpm test:e2e` が、エラーなく完了することを確認する。
